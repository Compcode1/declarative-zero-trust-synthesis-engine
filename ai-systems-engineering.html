DETERMINISTIC AI SYSTEMS ENGINEERING

Generative AI operates as a probabilistic engine, whereas enterprise Identity and Access Management (IAM) requires strict, binary precision—a cryptographic token or RBAC scope is either completely correct or it fails. To reconcile this difference, I designed the Zero Trust Interactive State Machine as a deterministic control harness. By taking a probabilistic model and tethering it to a master System Directive, the architecture governs the AI as a high-speed Infrastructure-as-Code compiler, maintaining absolute precision and zero-trust integrity.

Architectural Insight: The Compiler Paradigm
"Similar to how a software compiler translates human intent into machine execution through lexical analysis and validation checks, the Zero Trust Interactive State Machine compiles five polymorphic choices into cryptographically verified Microsoft Entra ID configurations. By binding an untethered language model within clear operational guidelines and execution constraints, we harness its speed without risking probabilistic drift."

[SECTION 01 :: SOFTWARE CLASSIFICATION]

Anatomy of the Deterministic Control Harness

The Zero Trust Interactive State Machine (v9.1) functions as a natural-language control system. It separates execution responsibilities cleanly between the synthesis engine, the state-space rulebook, and the compliance logging layer.

[LAYER 01 : COMPUTATIONAL ENGINE]

The Governed Synthesis Processor

The Large Language Model (LLM) is utilized exclusively as a high-speed syntax generator. It compiles environment-agnostic deployment payloads across Terraform (HCL), Azure Bicep, and Microsoft Graph REST APIs across 72 unique infrastructure baselines.

[LAYER 02 : STATE-SPACE CONTROL PLANE]

7 Directives & 32 Execution Rules

A structured sequence of 7 deployment phases governed by 32 un-bypassable mechanical rules. Specific rules enforce context isolation, ensuring that display text or chat descriptions never interfere with core execution logic.

[LAYER 03 : PRE-COMPILED COMPLIANCE]

Cryptographic Audit Ledgers

Instead of performing compliance checks manually after deployment, the system generates immutable audit proofs as standard outputs: the Identity Architecture Ledger (IAL), the Audit Results Ledger (ARL), asynchronous KQL Telemetry, and the Defect & Patch Ledger (DPL).

[SECTION 03 :: CORE PRINCIPLES & RUNTIME MECHANICS]

The Four Pillars of the State Machine

To keep the AI working reliably, the framework incorporates four foundational AI safety and engineering standards directly into its operating rules.

[PILLAR 01 :: ITERATIVE TELEMETRY GROUNDING]

1. Agentic Design Patterns & DPL Evolution

Standard workflows often struggle with single-pass generation. Aligned with established research on Agentic Workflows, this architecture guides the AI through structured Generate-Validate-Fix loops whenever API friction occurs.
v9.1 Runtime Implementation (Directive 05, Rule 9 & Rule 15)

When terminal errors arise, the engine evaluates the issue, states a clear Root Cause Hypothesis, and tracks iteration steps. Once resolved, Rule 15 logs the fix in the Defect & Patch Ledger (DPL) and Rule 9 regenerates the complete IaC file from scratch to prevent partial-patch errors and harden future runs.

Reference Standard
ReAct: Synergizing Reasoning and Acting in Language Models (Yao et al.)

Research from Princeton and Google Brain demonstrating that language models perform more reliably when alternating between reasoning steps and concrete environmental actions.

[PILLAR 02 :: BLAST-RADIUS CONTAINMENT]

2. Bounded Autonomy & MFA Decoupling

Unconstrained models can take unintended shortcuts when handling deployment errors. This framework protects against Excessive Agency by keeping the AI strictly bound within predefined state constraints.
v9.1 Runtime Implementation (Directive 01, Rule 3, Rule 4 & Rule 29)

The state machine restricts autonomous actions by blocking broad management roles (Owner/Contributor), enforcing prevent_destroy locks, and implementing Rule 29 (Data-Plane Decoupling): if local credential tools drop required MFA claims during role assignments, the engine pauses automation and directs the engineer through a manual Azure Portal workflow.

Reference Standard
OWASP Top 10 for LLM Applications (LLM08: Excessive Agency)

Application security guidance advising against granting large language models unconstrained permissions or unverified execution capabilities across systems.

[PILLAR 03 :: STRUCTURAL OVERSIGHT]

3. Human-in-the-Loop (HITL) Governance

Automated provisioning without verification presents governance risks. This architecture ensures every phase of the pipeline includes explicit authorization gates controlled by the human architect.
v9.1 Runtime Implementation (Rule 1, Rule 8, Rule 12 & Rule 28)

Rule 1 prevents rushing through execution steps by enforcing mandatory pauses across all 7 phases. Before applying changes, the system previews workspace files (Rule 12), confirms OIDC parameters, runs directory audit scripts (Rule 28), and waits for human sign-off.

Reference Standard
NIST Artificial Intelligence Risk Management Framework (AI RMF 1.0)

Federal standard establishing the "Govern" function—emphasizing transparent risk management and explicit human accountability for AI implementations.

[PILLAR 04 :: ANTI-HALLUCINATION PHYSICS]

4. Cognitive Circuit Breaking & Watchdog

Models can experience context degradation during long troubleshooting sessions. This architecture uses a deterministic circuit breaker to pause execution before errors compound.
v9.1 Runtime Implementation (Directive 02, Directive 05 & Directive 07)

Directive 07 runs continuous checks to maintain operational rules. If any troubleshooting sequence reaches Iteration 4, the Cognitive Circuit Breaker halts code generation—requiring a summary of error history and returning risk control back to the human architect.

Reference Standard
