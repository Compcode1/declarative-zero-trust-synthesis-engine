[PROJECT 02 :: TWO INDEPENDENTLY SCOPED WORKERS]

Two Workers, Separate Configuration Boundaries

A fleet-planning support job and a maintenance-support job may need different configuration even when they share an AWS account. This lab represents those jobs with two GitHub Actions workers. Each authenticates into a distinct IAM role and requests its own harmless Secrets Manager configuration.

Completed 15 November 2026 in account 698250246230, region us-east-2. Each worker retrieved and described its own configuration. Attempts to list secrets or retrieve the other worker’s configuration received the expected authorization denial.

Relation to Project 01. This extends the learning sequence to two separately scoped workers and explicit adjacent-secret tests. Lab 02 checks the expected denial response; Project 01’s historical script accepted arbitrary nonzero results. This lab did not rerun or upgrade Project 01’s evidence.

The workers simulate configuration access for autonomous-support services. They do not implement a planner, a maintenance system or vehicle controls. The lab ran under AWS v2.0 Language Candidate 01; later v2.0.1/v2.0.2 directives were not its tested runtime source.

infrastructure/main.tf — complete recorded source
terraform {
  required_version = ">= 1.10.0, < 2.0.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "= 6.73.0"
    }
    time = {
      source  = "hashicorp/time"
      version = "= 0.14.2"
    }
  }
}

provider "aws" {
  region              = var.aws_region
  profile             = var.aws_profile
  allowed_account_ids = [var.aws_account_id]

  default_tags {
    tags = {
      Project   = "AKCCE-AWS-Lab-02"
      ManagedBy = "Terraform"
      Purpose   = "Simulated worker configuration isolation"
    }
  }
}

data "aws_iam_openid_connect_provider" "github" {
  arn = "arn:aws:iam::${var.aws_account_id}:oidc-provider/token.actions.githubusercontent.com"

  lifecycle {
    postcondition {
      condition     = contains(self.client_id_list, "sts.amazonaws.com")
      error_message = "The shared GitHub OIDC provider must accept the sts.amazonaws.com audience."
    }
  }
}

locals {
  oidc_issuer = "token.actions.githubusercontent.com"
  subjects = {
    for key, worker in var.workers : key =>
    "repo:${var.github_owner}@${var.github_owner_id}/${worker.github_repo}@${worker.github_repo_id}:ref:refs/heads/${worker.github_branch}"
  }
  secret_read_actions = [
    "secretsmanager:GetSecretValue",
    "secretsmanager:DescribeSecret",
  ]
}

resource "aws_iam_role" "worker" {
  for_each = var.workers

  name                 = each.value.role_name
  description          = "Lab 02 worker ${each.key}: exact GitHub subject and single configuration secret."
  max_session_duration = 3600
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid    = "ExactGitHubWorkload"
      Effect = "Allow"
      Principal = {
        Federated = data.aws_iam_openid_connect_provider.github.arn
      }
      Action = "sts:AssumeRoleWithWebIdentity"
      Condition = {
        StringEquals = {
          "${local.oidc_issuer}:aud" = "sts.amazonaws.com"
          "${local.oidc_issuer}:sub" = local.subjects[each.key]
        }
      }
    }]
  })

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_secretsmanager_secret" "worker_config" {
  for_each = var.workers

  name                    = each.value.secret_name
  description             = "Harmless simulation configuration for fleet-support worker ${each.key}."
  recovery_window_in_days = var.secret_recovery_window_days

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_secretsmanager_secret_version" "worker_config" {
  for_each = var.workers

  secret_id     = aws_secretsmanager_secret.worker_config[each.key].id
  secret_string = jsonencode(each.value.configuration)

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_iam_role_policy" "worker_read" {
  for_each = var.workers

  name = "${each.value.role_name}-read-own-config"
  role = aws_iam_role.worker[each.key].id
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid      = "ReadOwnWorkerConfiguration"
      Effect   = "Allow"
      Action   = local.secret_read_actions
      Resource = aws_secretsmanager_secret.worker_config[each.key].arn
    }]
  })

  lifecycle {
    prevent_destroy = true
  }
}

resource "aws_secretsmanager_secret_policy" "worker_config" {
  for_each = var.workers

  secret_arn          = aws_secretsmanager_secret.worker_config[each.key].arn
  block_public_policy = true
  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid    = "AllowAssignedWorkerConfigRead"
      Effect = "Allow"
      Principal = {
        AWS = aws_iam_role.worker[each.key].arn
      }
      Action   = local.secret_read_actions
      Resource = aws_secretsmanager_secret.worker_config[each.key].arn
    }]
  })

  lifecycle {
    prevent_destroy = true
  }
}

resource "time_sleep" "iam_propagation" {
  create_duration = "30s"
  depends_on = [
    aws_iam_role_policy.worker_read,
    aws_secretsmanager_secret_policy.worker_config,
    aws_secretsmanager_secret_version.worker_config,
  ]

  triggers = {
    policy_digest = sha256(jsonencode({
      role_policies   = { for key, item in aws_iam_role_policy.worker_read : key => item.policy }
      secret_policies = { for key, item in aws_secretsmanager_secret_policy.worker_config : key => item.policy }
    }))
  }
}

Worker A — recorded validate-bridge.yml
name: Lab 02 Worker a Configuration Isolation

on:
  push:
    branches: [main]
    paths: ['.github/workflows/validate-bridge.yml']
  workflow_dispatch:

permissions:
  id-token: write
  contents: read

concurrency:
  group: lab02-worker-a-${{ github.ref }}
  cancel-in-progress: false

jobs:
  validate:
    runs-on: ubuntu-24.04
    timeout-minutes: 5
    env:
      AWS_PAGER: ""
      AWS_REGION: us-east-2
      AWS_DEFAULT_REGION: us-east-2
      WORKER_ID: a
      OWN_ROLE_ARN: arn:aws:iam::698250246230:role/akcce-fleet-02-worker-a-role
      OWN_SECRET_ARN: arn:aws:secretsmanager:us-east-2:698250246230:secret:autonomy-lab/fleet-02/worker-a/config-Sm8XS1
      OTHER_SECRET_ARN: arn:aws:secretsmanager:us-east-2:698250246230:secret:autonomy-lab/fleet-02/worker-b/config-joigf3
      EXPECTED_SESSION_PREFIX: arn:aws:sts::698250246230:assumed-role/akcce-fleet-02-worker-a-role/
    steps:
      - name: Checkout
        uses: actions/checkout@v4

      - name: Obtain temporary AWS credentials through OIDC
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ env.OWN_ROLE_ARN }}
          aws-region: ${{ env.AWS_REGION }}
          audience: sts.amazonaws.com
          role-session-name: lab02-worker-a-${{ github.run_id }}-${{ github.run_attempt }}
          role-duration-seconds: 900
          mask-aws-account-id: true

      - name: Verify acting worker identity
        shell: bash
        run: |
          set -euo pipefail
          identity=$(aws sts get-caller-identity --query Arn --output text)
          [[ "$identity" == "$EXPECTED_SESSION_PREFIX"* ]]
          printf 'LAB02_IDENTITY worker=%s arn=%s run=%s attempt=%s\n' "$WORKER_ID" "$identity" "$GITHUB_RUN_ID" "$GITHUB_RUN_ATTEMPT"

      - name: Retrieve and immediately mask own configuration
        shell: bash
        run: |
          set -euo pipefail
          secret=$(aws secretsmanager get-secret-value --secret-id "$OWN_SECRET_ARN" --query SecretString --output text)
          printf '::add-mask::%s\n' "$secret"
          jq -e --arg worker "$WORKER_ID" '.worker_id == $worker and .simulation_only == true and .fleet_actuation_enabled == false' <<< "$secret" >/dev/null
          unset secret
          described=$(aws secretsmanager describe-secret --secret-id "$OWN_SECRET_ARN" --query ARN --output text)
          [[ "$described" == "$OWN_SECRET_ARN" ]]
          printf 'LAB02_POSITIVE worker=%s target=%s result=SUCCESS http=200\n' "$WORKER_ID" "$OWN_SECRET_ARN"

      - name: Verify lateral enumeration is denied
        shell: bash
        run: |
          set -euo pipefail
          set +e; aws secretsmanager list-secrets --max-items 1 >/dev/null 2>&1; EXIT_CODE=$?; set -e
          [[ "$EXIT_CODE" -eq 254 ]]
          error_file="$RUNNER_TEMP/lab02-list-error.txt"
          set +e
          aws secretsmanager list-secrets --max-items 1 >/dev/null 2>"$error_file"
          classified_exit=$?
          set -e
          [[ "$classified_exit" -eq 254 ]]
          grep -Fq '(AccessDeniedException)' "$error_file"
          grep -Fq 'ListSecrets operation' "$error_file"
          rm -f "$error_file"
          printf 'LAB02_ENUM_DENIED worker=%s exit=%s error=AccessDeniedException\n' "$WORKER_ID" "$EXIT_CODE"

      - name: Verify the other worker configuration is denied
        shell: bash
        run: |
          set -euo pipefail
          error_file="$RUNNER_TEMP/lab02-cross-error.txt"
          set +e
          aws secretsmanager get-secret-value --secret-id "$OTHER_SECRET_ARN" >/dev/null 2>"$error_file"
          cross_exit=$?
          set -e
          [[ "$cross_exit" -eq 254 ]]
          grep -Fq '(AccessDeniedException)' "$error_file"
          grep -Fq 'GetSecretValue operation' "$error_file"
          rm -f "$error_file"
          printf 'LAB02_CROSS_DENIED worker=%s target=%s exit=%s error=AccessDeniedException\n' "$WORKER_ID" "$OTHER_SECRET_ARN" "$cross_exit"

      - name: Record selected checks
        shell: bash
        run: |
          set -euo pipefail
          printf 'LAB02_RESULT worker=%s own_get=SUCCESS describe=SUCCESS list=AccessDeniedException cross_get=AccessDeniedException\n' "$WORKER_ID"

Both actions still use mutable @v4 tags; immutable action commit pinning remains a hardening gap.
