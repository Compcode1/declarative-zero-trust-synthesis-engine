[PROJECT 03 :: ROLE ADMISSION & CONFIGURATION ACCESS]

Two Authorization Boundaries, Tested Together

Project 03 successfully tested two distinct authorization boundaries: which AWS role a worker can enter and which configuration it can access. Each intended worker obtained its own role and read its own configuration. Attempts to enter the opposite role or read the opposite secret were denied, and the outcomes were correlated with AWS CloudTrail records.

Separate identities let automated jobs work with different configuration without sharing the same authority. This demonstration implements that separation with two GitHub Actions workers, two AWS roles and two harmless configuration secrets. It tests the intended paths and then deliberately challenges the boundary between them.

Progress from Project 02: the earlier demonstration tested configuration isolation after a worker entered its own role. Project 03 adds a direct challenge to role admission itself: the same GitHub identity token accepted by the worker’s own role is presented to the opposite role. Both opposite-role requests were rejected.

Scope: this demonstrates CI/workload role admission and configuration access. It does not implement device enrollment, firmware signing or vehicle operation.

Lab provenance: 15 November 2026, America/Los_Angeles (PST); selected events on 16 November UTC. Account 698250246230 • region us-east-2 • executed source AWS v2.0.2.

[ARCHITECTURE :: ADMISSION BEFORE RESOURCE ACCESS]

Separate Identities, Explicit Access Paths

The architecture gives each worker its own AWS role and its own configuration. GitHub identifies the job, AWS checks whether that identity may enter the requested role, and the role’s effective permissions determine which configuration operations succeed.

In implementation terms, each worker obtains one GitHub OIDC token for audience sts.amazonaws.com. Its own role accepts the exact repository subject and issues temporary credentials. A separate direct AssumeRoleWithWebIdentity request presents that same token to the opposite role, testing admission independently of ordinary AssumeRole role chaining.

resource "aws_iam_role" "worker" {
  for_each             = var.workers
  name                 = each.value.role_name
  description          = "Lab 03 worker ${each.key}: exact GitHub subject and own configuration."
  max_session_duration = 3600
  assume_role_policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Sid    = "ExactGitHubWorkload"
      Effect = "Allow"
      Principal = {
        Federated = data.aws_iam_openid_connect_provider.github.arn
      }
      Action = "sts:AssumeRoleWithWebIdentity"
      Condition = {
        StringEquals = {
          "${local.oidc_issuer}:aud" = "sts.amazonaws.com"
          "${local.oidc_issuer}:sub" = local.subjects[each.key]
        }
      }
    }]
  })
  lifecycle {
    prevent_destroy = true
  }
}

.github/scripts/oidc-token.mjs — shared by both workers
import fs from 'node:fs';
import path from 'node:path';
const e = process.env;
try {
  const url = new URL(e.ACTIONS_ID_TOKEN_REQUEST_URL);
  if (url.protocol !== 'https:') throw new Error();
  url.searchParams.set('audience', 'sts.amazonaws.com');
  const response = await fetch(url, {
    headers: {Authorization: `Bearer ${e.ACTIONS_ID_TOKEN_REQUEST_TOKEN}`},
    redirect: 'error', signal: AbortSignal.timeout(30000)
  });
  if (response.status !== 200) throw new Error();
  const {value: token} = await response.json();
  if (typeof token !== 'string' || token.split('.').length !== 3) throw new Error();
  console.log(`::add-mask::${token}`);
  const claims = JSON.parse(Buffer.from(token.split('.')[1], 'base64url'));
  if (claims.iss !== 'https://token.actions.githubusercontent.com' ||
      claims.aud !== 'sts.amazonaws.com' || claims.sub !== e.EXPECTED_SUBJECT ||
      !Number.isFinite(claims.exp) || claims.exp <= Date.now() / 1000 + 60) throw new Error();
  const file = path.join(e.RUNNER_TEMP, 'lab03-oidc.jwt');
  fs.writeFileSync(file, token, {mode: 0o600, flag: 'wx'});
  fs.appendFileSync(e.GITHUB_ENV, `LAB03_TOKEN_FILE=${file}\n`);
  console.log(`LAB03_TOKEN_CONTEXT worker=${e.WORKER_ID} sub=${claims.sub} aud=${claims.aud}`);
} catch {
  console.error('LAB03_OIDC_FETCH_OR_CONTEXT_FAILED');
  process.exitCode = 1;
}

import fs from 'node:fs';
const e = process.env;
try {
  const token = fs.readFileSync(e.LAB03_TOKEN_FILE, 'utf8');
  const claims = JSON.parse(Buffer.from(token.split('.')[1], 'base64url'));
  if (claims.iss !== 'https://token.actions.githubusercontent.com' ||
      claims.aud !== 'sts.amazonaws.com' || claims.sub !== e.EXPECTED_SUBJECT ||
      !Number.isFinite(claims.exp) || claims.exp <= Date.now() / 1000 + 15 || !e.LAB03_SESSION_ARN) throw new Error();
  const start = new Date().toISOString();
  const session = `lab03-deny-${e.WORKER_ID}-${e.GITHUB_RUN_ID}-${e.GITHUB_RUN_ATTEMPT}`;
  const body = new URLSearchParams({
    Action: 'AssumeRoleWithWebIdentity', Version: '2011-06-15',
    RoleArn: e.OTHER_ROLE_ARN, RoleSessionName: session,
    WebIdentityToken: token, DurationSeconds: '900'
  });
  const response = await fetch('https://sts.us-east-2.amazonaws.com/', {
    method: 'POST', body, redirect: 'error', signal: AbortSignal.timeout(30000)
  });
  const end = new Date().toISOString();
  if (response.ok) {
    await response.body?.cancel();
    console.error('LAB03_ISOLATION_FAILED: opposite-role credential issuance; response discarded');
    process.exitCode = 1;
  } else {
    const xml = await response.text();
    const code = xml.match(/<Code>([^<]+)<\/Code>/)?.[1];
    const requestId = xml.match(/<RequestId>([A-Za-z0-9-]+)<\/RequestId>/)?.[1] ||
      response.headers.get('x-amzn-requestid') || 'NOT_RETURNED';
    if (response.status !== 403 || code !== 'AccessDenied' ||
        claims.exp <= Date.now() / 1000) throw new Error();
    console.log('LAB03_WEBIDENTITY_DENIED ' + JSON.stringify({
      worker: e.WORKER_ID, operation: 'AssumeRoleWithWebIdentity',
      target: e.OTHER_ROLE_ARN, error: code, http: response.status,
      request_id: requestId, start, end, role_session_name: session,
      own_session: e.LAB03_SESSION_ARN, sub: claims.sub, aud: claims.aud,
      repository: e.GITHUB_REPOSITORY, commit: e.GITHUB_SHA,
      run: e.GITHUB_RUN_ID, attempt: e.GITHUB_RUN_ATTEMPT
    }));
  }
} catch {
  console.error('LAB03_WEBIDENTITY_PROOF_UNRESOLVED: no accepted authorization-denial evidence');
  process.exitCode = 1;
}
